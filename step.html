附表一　作業步驟與資料交換清單

編號對應第一頁流程圖。「系統自動」指平台或銀行系統依規則執行，「人工」指由客戶或銀行人員操作。

編號階段執行角色作業方式傳遞欄位保存範圍
①一、需求授權客戶人工協助需求代碼清單客戶紀錄（需求代碼、操作時間）
②一、需求授權客戶人工接收銀行代碼清單、同意版本與時間同意紀錄，依個資保存規定辦理
③一、需求授權平台系統自動案件編號、每家銀行的授權範圍（僅含該行的需求代碼）平台案件資料；各行資料互不相通
④二、派送與導轉平台系統自動該行介接狀態（是否已完成 Open API 介接）平台介接狀態表
4a二、派送與導轉平台系統自動狀態：尚未開放客戶紀錄（僅狀態，不產生授權請求）
⑤二、派送與導轉平台、客戶瀏覽器、銀行系統導轉＋客戶操作導轉參數：平台識別碼、授權範圍（需求代碼）、state（防偽參數）、回傳位址導轉紀錄；state 使用後失效
⑥三、身分驗證與授權銀行人工（客戶於銀行頁完成）銀行自有驗證資料，不回傳平台依銀行本身規定保存
6a三、身分驗證與授權銀行系統自動驗證失敗代碼（不含個人資料內容）平台僅記錄「未完成授權」狀態
⑦三、身分驗證與授權銀行、客戶瀏覽器、平台系統自動一次性授權碼、state；平台以授權碼換取存取權杖（綁定授權範圍與期限）授權碼用後即失效；權杖存放於平台憑證庫，到期或撤回即失效
⑧四、接件、服務安排與回覆銀行系統自動銀行以存取權杖呼叫平台 API，取得授權範圍內的案件編號與需求代碼銀行收件紀錄；權杖之外的資料不可取得
⑨四、接件、服務安排與回覆銀行人工服務安排內容、回覆代碼、補充說明（300 字以內）依銀行本身規定保存
⑩四、接件、服務安排與回覆銀行、平台系統自動回覆代碼、補充說明、回覆時間、狀態平台客戶紀錄（回覆內容）
⑪四、接件、服務安排與回覆客戶人工無（僅查閱）—
⑫五、單獨撤回客戶人工撤回指令（案件編號、銀行代碼）撤回紀錄
⑬五、單獨撤回平台系統自動撤銷該行存取權杖；撤回通知撤回紀錄
⑭五、單獨撤回銀行系統自動權杖失效通知；停止查閱銀行依規定保存已收資料

附表二　異常情境與責任歸屬

停止點指流程在哪一步終止；接手單位指後續由誰處理。

情境觸發步驟流程停止點接手單位客戶可見結果
銀行未完成 Open API 介接④ → 4a平台。不產生導轉，不建立授權請求。平台營運單位，與該行介接窗口協調。紀錄顯示「尚未開放」，客戶可隨時再次嘗試。
身分驗證失敗，或客戶無法使用銀行 App⑥ → 6a銀行授權頁。授權中止，不回傳授權碼。銀行，依本行替代驗證流程處理（如臨櫃、語音或其他已開放管道）。紀錄顯示「未完成授權」，客戶可重新導轉。純網銀 B 無實體分行，以線上替代驗證為主。
授權資料不符（state 與平台記錄不一致，或權杖範圍與案件不符）⑦平台。拒收授權碼，不換取權杖。平台資安與營運單位，留存異常紀錄並進行原因分析。顯示「授權失敗，請重新操作」，不顯示任何需求內容。
銀行收件後發現資料與客戶不符⑧銀行。停止處理，不安排服務。銀行，依本行流程處理，並通知平台撤銷該行權杖。該行狀態顯示「已退回」，客戶可重新送出。
客戶單獨撤回某一家銀行⑫ → ⑬ → ⑭平台。立即撤銷該行權杖，停止查閱。平台自動處理；已安排的服務由客戶直接與該行聯繫。該行狀態顯示「已撤回」，其他銀行不受影響。

法規法規要求本案設計對策對應步驟
《個人資料保護法》 蒐集健康相關資料屬特種個資，蒐集須有特定目的，並履行告知與取得同意義務；利用不得逾越目的範圍；委託他人處理時，委託機關須為監督。 同意書明列目的（安排金融友善服務）、接收機構與保存期限。平台只傳遞授權範圍內的需求代碼，不傳遞身分證字號、病況描述或其他個人資料。平台與各行另簽資料傳遞與委外約定。 ①、②、③、⑧
《金融機構間資料共享指引》 金融機構間共享客戶資料，應以客戶同意為前提，限定於明確用途，並建立內部控管與紀錄。 資料共享以客戶逐行授權為前提，授權範圍逐項列明。各行只取得自己的授權範圍，平台不做跨行資料彙整。 ②、⑤、⑧
《電子銀行業務安全控管作業基準》 電子銀行服務應採取適當的身分驗證、資料傳輸加密，並保存必要的存取與交易紀錄。 身分驗證由銀行於其授權頁完成，平台不接觸客戶的驗證資料。授權碼一次性使用，權杖限定範圍與期限。傳輸採加密通道，存取紀錄完整留存。 ⑥、⑦、⑧、⑩
《銀行業金融友善服務準則》 銀行應依客戶需求提供友善服務，並以客戶實際需求安排服務方式。 需求項目依準則的服務類別列出。各行逐項回覆安排方式，並可補充說明。客戶隨時可撤回單一銀行的分享。 ①、⑨、⑫
財金公司開放銀行相關技術標準 介接應採用標準化 API 與 OAuth 授權流程，並符合資訊安全要求。 採 OAuth 授權導轉，搭配 state 防偽參數與存取權杖。權杖限縮授權範圍與期限，撤回時立即撤銷，並保留完整日誌。 ④、⑤、⑦、⑧、⑬
